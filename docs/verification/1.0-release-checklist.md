# Hum 1.0 release checklist

Last reviewed: 2026-08-19

This is the pass or stop authority for Hum 1.0. Record evidence beside each item or link to a durable test report. A required failure blocks release.

## Stop conditions

- [ ] Every phase currently listed in the 1.0 roadmap is Complete. Removing a phase requires a reviewed roadmap and checklist change before release review resumes.
- [ ] Every open `BUGS.md` item is fixed, moved to an explicit known limitation in the release evidence, or assigned after 1.0 with its customer impact documented.
- [ ] No release artifact is unsigned or built from an uncommitted tree.
- [ ] The updater public key is configured and a real signed update has passed.
- [ ] License activation, offline verification, and restore have passed against production services.
- [ ] Pricing, refund, privacy, support, and website claims match the shipped app.
- [ ] No developer menu, fake update path, test endpoint, debug log, or placeholder credential ships.
- [ ] No required check below is waived without a new accepted ADR and a revised release contract.

## Purchase and first run

- [ ] A new customer can move from checkout to an activated app without developer help.
- [ ] Canceling checkout returns to a clear, usable state.
- [ ] Invalid, revoked, unavailable, and offline license states explain what happened.
- [ ] License restore works after uninstall and reinstall.
- [ ] Secrets and license tokens do not appear in logs, settings JSON, URLs, or diagnostics exports.
- [ ] First-run setup covers placement, listening output, appearance, shortcuts, and recovery from Ghost mode.
- [ ] The user can reopen onboarding or help later.
- [ ] About, support, privacy, license status, and update status are reachable from the tray or Settings.
- [ ] Paid installs do not show promotional cards by default.

## Player and source compatibility

- [ ] Spotify desktop track, artist, artwork, duration, position, pause, seek, and track change pass.
- [ ] Spotify web in Chrome and Edge passes the supported metadata and timing matrix.
- [ ] YouTube Music web in Chrome and Edge passes the supported metadata and timing matrix.
- [ ] Standard YouTube music videos pass title cleanup, artwork, duration, and lyric lookup.
- [ ] iTunes desktop track, artist, artwork, duration, position, pause, seek, and track change pass.
- [ ] Pandora web passes track, artist, ad, pause, and timing behavior.
- [ ] Pandora desktop passes every behavior Hum claims to support.
- [ ] At least one TIDAL, VLC, foobar2000, MusicBee, or other SMTC player passes the generic path.
- [ ] Multiple active media sessions follow the documented priority rule.
- [ ] Unsupported video services show the correct branded state and never send dialogue metadata to lyric providers.
- [ ] Closing, crashing, or restarting the active player returns Hum to a recoverable state.

## Lyric quality and timing

- [ ] Strict title, artist, and duration matching rejects a known wrong recording.
- [ ] A supported NetEase YRC song displays word timing with exact token spacing.
- [ ] LRCLib line timing remains available when word timing is missing or malformed.
- [ ] NetEase line timing remains available when LRCLib has no usable result.
- [ ] Plain lyrics render without pretending to be synchronized.
- [ ] Instrumental, unavailable, provider error, metadata mismatch, and offline states are distinct.
- [ ] Pausing freezes word and line progress.
- [ ] Seeking forward and backward moves to the correct line and word.
- [ ] Temporary nudge, per-song correction, expert calibration, and device delay combine according to the documented equation.
- [ ] The Lyrics Control Center can search, preview, choose, edit, import, restore, retry, and clear the current song.
- [ ] Local corrections survive restart and work offline.
- [ ] Desktop and OBS select the same lyric record and timing.
- [ ] Unicode, punctuation, blank lines, long lines, right-to-left text, and translations render without data loss.

## Audio-device timing

- [ ] Wired, USB, Bluetooth, HDMI, and built-in output profiles retain independent delays.
- [ ] Changing the Windows default output selects the correct profile while music is playing.
- [ ] Device rename, disconnect, reconnect, and removal preserve or recover profile assignment.
- [ ] A user can manually override automatic selection.
- [ ] The calibration tool makes earlier and later adjustments understandable.
- [ ] The selected profile and delay are consistent in Settings, tray, desktop overlay, and OBS.
- [ ] Existing v0.13.52 listening-mode settings migrate without data loss.

## Overlay and displays

- [ ] Ribbon and Square open at valid positions on the active display.
- [ ] Three-line, single-line, Full page, and Square presentations pass their layout matrix.
- [ ] Every built-in preset passes at its minimum and normal sizes.
- [ ] The active lyric does not move or resize when nearby content changes.
- [ ] Edit, Locked, and Ghost modes remain recoverable through tray and shortcuts.
- [ ] Window placement survives app restart, shape changes, and display reconnect.
- [ ] Mixed-DPI multi-monitor behavior passes at 100, 125, 150, and 200 percent scaling.
- [ ] Hum never restores entirely offscreen after a resolution, scaling, or monitor change.
- [ ] Fullscreen applications, task switching, sleep, wake, and display hot-plug do not strand the overlay.
- [ ] Missing, corrupt, and changing album artwork do not flash or break the surface.
- [ ] Every native backdrop option has a polished fallback.

## Accessibility

- [ ] Every Settings control has a useful accessible name and keyboard focus state.
- [ ] Keyboard navigation can reach every required action without trapping focus.
- [ ] Screen-reader output identifies the current page, control, value, and error state.
- [ ] Large text remains readable without covering required controls.
- [ ] High-contrast settings remain usable in every built-in preset.
- [ ] Reduced motion removes nonessential transitions while preserving lyric timing feedback.
- [ ] Shortcut customization reports conflicts and provides a reset action.
- [ ] Color is never the only indicator of status or selection.

## Creator Studio and OBS

- [ ] The default OBS URL works after copy and paste into a clean browser source.
- [ ] Live preview matches OBS at 720p, 1080p, 1440p, and 4K.
- [ ] Lower third, ribbon, square, karaoke, and full-sheet templates pass.
- [ ] Transparent, chroma, and solid backgrounds pass.
- [ ] Safe-area guides match the selected canvas and stay out of the rendered output.
- [ ] Four simultaneous output profiles remain synchronized without duplicate provider requests.
- [ ] Port conflict, server restart, sleep, wake, and OBS reconnect show accurate health states.
- [ ] The server binds to loopback by default and rejects unsafe Host headers.
- [ ] Creator profile import rejects invalid data without losing existing profiles.
- [ ] Word timing, translation, local correction, pause, seek, and device delay match the desktop overlay.

## Offline and failure behavior

- [ ] Cached lyrics start without a network connection.
- [ ] Local edits remain available after provider cache is cleared.
- [ ] Provider timeout falls back within the documented time budget.
- [ ] Lyrics, artwork, artist information, promos, license, and updater failures do not crash playback tracking.
- [ ] Corrupt cache and settings files recover without deleting unrelated user data.
- [ ] A full disk, read-only folder, blocked port, and unavailable screen sampling produce useful errors or safe fallbacks.
- [ ] Hum recovers after the network disappears and returns during playback.
- [ ] Every retry action is bounded and cannot create an uncontrolled request loop.

## Performance and stability

- [ ] Cold start reaches a usable overlay within 3 seconds on the baseline release machine.
- [ ] A cached lyric appears within 500 ms after stable metadata arrives.
- [ ] An uncached lyric resolves or reaches a useful fallback state within 4 seconds under normal network conditions.
- [ ] Average playback CPU stays below 3 percent during a 30-minute baseline run.
- [ ] Total working set stays below 250 MB after a 2-hour mixed playback run.
- [ ] One hundred track changes do not cause monotonic memory growth above 20 MB after settling.
- [ ] Idle, paused, hidden, and nothing-playing states reduce polling and rendering work.
- [ ] A 4-hour run with tracks, pauses, seeks, ads, device changes, sleep, and wake completes without a crash or frozen overlay.
- [ ] Production logs contain no unbounded repeated warning.

- [ ] Remote image and promo URLs are validated before use.
- [ ] Localhost services enforce loopback binding and Host validation.
- [ ] Imported profile and lyric files are size-limited and parsed without executing content.
- [ ] Diagnostics redact secrets and license material.
- [ ] Dependency audit has no unresolved high-severity advisory in shipped code.

## Rollback procedure

Hum 1.0 supports two rollback actions: withdrawing the release from the update feed and manually reinstalling the prior signed build. Automatic downgrade is not supported.

- [ ] The previous signed installer and update metadata remain available before publishing 1.0.0.
- [ ] The release owner can remove 1.0.0 from the update feed without deleting customer data.
- [ ] A standard user can manually reinstall the prior signed build, and compatible settings, lyric cache, local edits, licenses, and creator profiles remain usable.
- [ ] Settings, lyric cache, local edits, licenses, and creator profiles are backward-compatible or have a tested recovery path.
- [ ] Support messaging for a paused or rolled-back release is prepared.

## Post-release verification

- [ ] A clean external machine receives and launches the public artifact.
- [ ] The public updater endpoint returns the expected signed metadata.
- [ ] Purchase, activation, download, and support links work from the production website.
- [ ] The support inbox and customer-submitted diagnostics intake are checked after 1 hour, 24 hours, and 7 days.
